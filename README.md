# Picstome documentation

Public help center for Picstome, published at **https://docs.picstome.com**.

Built with [Starlight](https://starlight.astro.build) (Astro). Every article is a
plain Markdown/MDX file, in English (root) and Spanish (`/es/`), with a static
search index generated by Pagefind at build time.

## What lives here

```
src/content/docs/          Articles. `es/` mirrors the same slugs in Spanish.
src/assets/screens/        Screenshots used by the articles (generated).
src/components/            HelpMeta, Screenshot, Video, StatusBoard.
src/integrations/          help-export.mjs: emits api/help-{en,es}.json.
src/styles/                Picstome brand layer on top of Starlight.
public/videos/             Short silent clips (WebM + WebP poster).
demo/                      Demo dataset, photo sources and the capture script.
scripts/                   verify.mjs (CI checks) and screens.mjs (media wiring).
```

## Commands

```bash
npm install
npm run dev        # local dev server
npm run build      # build + verify (fails on broken slugs, links or media)
npm run preview    # serve the built site
npm run verify     # checks only
```

## Writing an article

1. Create `src/content/docs/<section>/<slug>.mdx` **and** the Spanish twin in
   `src/content/docs/es/<section>/<slug>.mdx`. The build fails if one of the two
   is missing.
2. Start with the `<HelpMeta />` block. `section` is the stable id the panel uses
   to open the article:

   ```mdx
   ---
   title: "Favorites and the selection limit"
   description: "One sentence for the search engine."
   help:
     section: sharing.selection
     summary: "One or two sentences shown above the fold in the panel."
     appRoutes: [galleries.show, shares.show]
   ---

   import HelpMeta from '@components/HelpMeta.astro';

   <HelpMeta
     section="sharing.selection"
     summary="One or two sentences shown above the fold in the panel."
     routes={['galleries.show', 'shares.show']}
   />
   ```

3. Write for a photographer, not for a developer: **what this does, when to use
   it, and what the client sees**. If a feature is obvious, it does not need an
   article.
4. Add the sidebar entry in `astro.config.mjs` (label + Spanish translation).

## Screenshots and videos

Captures come from the application, never from a hand-made screenshot:

```bash
# 1. Seed the demo studio (needs a running Picstome)
php artisan tinker /workspace/projects/picstome-docs/demo/seed.php

# 2. Capture everything (or --lang es, --only selection, --video)
node demo/capture.mjs --video

# 3. Wire the new files into the articles
node scripts/screens.mjs
```

- Captures land in `src/assets/screens/`; the Spanish ones get an `-es` suffix.
- Clips land in `public/videos/` as WebM (VP9, no audio) with a `.webp` poster.
- `demo/photos/` holds the free-licence photos used by the demo; see
  `demo/photos/SOURCES.md`.
- `demo/state.json` is generated and git-ignored: it tells the capture script
  which gallery id and public link the local database assigned.

## Publishing

Cloudflare Pages, project `picstome-docs`, connected to this repository:

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | 22 |
| Custom domain | `docs.picstome.com` |

`docs.picstome.com` resolves to `picstome-docs.pages.dev`, so the Pages project
must keep that exact name until the DNS record changes.

## Conventions

- **Spanish from Spain**, **English from the US**. Both are written, not
  translated word by word.
- No technical jargon in the customer articles. `self-hosting` is the only
  technical page and it is explicitly labelled.
- Every image needs a real `alt`; the verify script warns when one is missing.
- `npm run build` must pass before opening a pull request: it is the same check
  Cloudflare runs.
